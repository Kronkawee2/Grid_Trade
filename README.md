# Quant Grid ML — Adaptive Grid Research

EURUSD และ XAUUSD จาก Dukascopy (ข้อมูลสร้างจาก tick ย้อนหลัง 20-23 ปี) มาทดสอบสมมติฐานที่ว่าระบบกริดซึ่งปรับขนาดตามความผันผวนและมีการควบคุมความเสี่ยงที่รัดกุม สามารถสร้างผลตอบแทนที่เป็นบวกอย่างต่อเนื่องบนทุนขนาดเล็ก ($100) ได้จริงหรือไม่ วิธีทดสอบคือสร้าง baseline ที่ตรวจสอบได้ก่อน แล้วเปิดฟีเจอร์ทีละอย่างเพื่อดูว่าอะไรคือสิ่งที่ทำให้ระบบรอด ไม่เชื่อผลรวมที่ดูดี แต่ทุกการเปลี่ยนแปลงต้องทำให้ทั้งสองตลาดดีขึ้นพร้อมกันโดยไม่จูนค่าแยกรายตลาด

ชื่อโปรเจกต์มีคำว่า ML แต่ยังไม่มี ML อยู่ในนั้น เพราะโมเดลจะวัดผลได้ก็ต่อเมื่อมี baseline ให้เทียบ และการสร้าง baseline ที่เชื่อถือได้กลายเป็นงานเกือบทั้งหมดของโปรเจกต์นี้

## ผลการทดลอง

ทดสอบระบบกริด 5 เวอร์ชัน (ตั้งแต่กริดเปล่าจนถึงเวอร์ชันที่มีการควบคุมครบ) กับ 2 สินทรัพย์ที่ไม่เกี่ยวข้องกัน บนข้อมูล 19 ปีชุดเดียวกัน โดยใช้ค่าพารามิเตอร์ชุดเดียวทั้งสองตลาด ไม่มีการจูนแยก จากนั้นตรวจ baseline ด้วย 3 ด่าน แล้วแก้ค่าที่พบว่าตั้งผิด

ผลสรุป: **ระบบทำกำไรได้ทั้งสองตลาด กำไรทุกปี 19 จาก 19 ปี และผ่าน walk-forward** แต่ยังไม่พร้อมเรียกว่าพิสูจน์แล้ว เพราะ (1) **ยังไม่เคยรันจริงแม้แต่บนบัญชีเดโม** (2) **53-56% ของวันทั้งหมด บัญชีไม่ทำจุดสูงสุดใหม่** โดยช่วงที่นิ่งยาวที่สุดคือ 1.1 ปี และ (3) ค่าปัจจุบันเพิ่งถูกแก้ ยังไม่ได้ผ่าน walk-forward ซ้ำหลังแก้

สิ่งที่พิสูจน์ได้ชัดเจนคือ **มูลค่าทั้งหมดของระบบอยู่ที่การควบคุมความเสี่ยง ไม่ได้อยู่ที่ตัวกริด** — กริดเปล่าๆ พอร์ตแตกทุกกรณี และตัวที่พลิกจาก "แตก" เป็น "กำไร" คือเพดานตัดวงจร ไม่ใช่กลไกการวางออเดอร์

## ทำไมระบบกริดถึงล้างพอร์ต

กริดคือการวางออเดอร์ limit เป็นชั้นๆ รอบราคาปัจจุบัน แล้วเก็บกำไรทีละน้อยเมื่อราคาแกว่งไปมา ปัญหาคือมันสวนทางตลาดโดยธรรมชาติ

* **เมื่อตลาดแกว่งในกรอบ:** ราคาวิ่งขึ้นลงผ่านชั้นต่างๆ เก็บกำไรได้เรื่อยๆ ดูเหมือนเครื่องพิมพ์เงิน
* **เมื่อตลาดวิ่งทางเดียว:** ทุกชั้นถูกเปิดหมดและขาดทุนพร้อมกัน ยิ่งราคาไปไกลยิ่งขาดทุนมาก ไม่มีจุดจบในตัวมันเอง

ระบบกริดส่วนใหญ่จึงมี equity curve ที่สวยงามเป็นเดือนหรือเป็นปี **แล้วจบในวันเดียว** และไม่มีสัญญาณเตือนล่วงหน้า โปรเจกต์นี้จึงตั้งโจทย์ที่การควบคุมความเสียหายก่อน ไม่ใช่ที่การหากำไร

## หลักการทำงานทั้งหมด: 5 ชั้น

ทุกชั้นถูกเพิ่มเข้ามาตามลำดับ และแต่ละชั้นถูกวัดผลแยกว่าให้อะไรบ้าง (ไม่มี Machine Learning เป็นกฎเชิงกลไกล้วน)

### ชั้น 1 — กริดที่ปรับตามความผันผวน (นี่คือคำว่า "adaptive")

ระยะห่างระหว่างชั้นไม่ใช่ค่าคงที่ แต่เป็น `5.0 × ATR(10)` คำนวณใหม่ทุกครั้งที่ปักหมุด แล้วล็อกไว้ตลอดรอบนั้น เป้ากำไร ระยะ stop และระยะรอเด้ง ล้วนเป็นสัดส่วนของระยะห่างนี้ จึงขยายและหดตามไปด้วยทั้งหมด

**แต่มันช่วยจริงแค่ไหน วัดได้** โดยเปลี่ยนบรรทัดเดียว: แทน `× ATR` ด้วยตัวเลขคงที่ แล้วเก็บทุกอย่างอื่นไว้เหมือนเดิม

#### บนตลาดเดียว — ไม่ได้ช่วยเรื่องกำไร

| ระยะห่าง | EURUSD จบที่ | maxDD |
| :--- | ---: | ---: |
| **ปรับตาม ATR** | $594 | **36%** |
| คงที่ 15 pip | **แตก** | 209% |
| คงที่ 20 pip | **แตก** | 174% |
| คงที่ 25 pip | $248 | 97% |
| คงที่ 30 pip | $513 | 70% |
| คงที่ 40 pip | **$685** | 35% |

*(ตารางนี้วัดด้วยค่าชุดก่อนการแก้ แต่ข้อสรุปไม่เปลี่ยน)*

ระยะคงที่ 40 pip ทำเงินได้มากกว่าเล็กน้อยที่ความเสี่ยงพอกัน **แต่อีกสี่ค่าจากห้าค่าให้ DD 70-209% หรือพอร์ตแตก** ต้องรู้ล่วงหน้าว่า 40 คือคำตอบถึงจะชนะได้ ซึ่งรู้ไม่ได้

#### ข้ามตลาด — ตรงนี้คือจุดที่มันสำคัญ

เอาค่าที่ดีที่สุดจาก EURUSD (40 pip) ไปใช้กับทองคำโดยตรง

| ระยะห่าง | ทองคำ จบที่ | maxDD |
| :--- | ---: | ---: |
| **ปรับตาม ATR** | **$1,096** | **21%** |
| คงที่ 25 pip | **แตก** | 236% |
| คงที่ 40 pip | $351 | 60% |

**แย่กว่า 3 เท่าทั้งกำไรและความเสี่ยง** เพราะ 40 pip ที่พอดีกับตลาดที่ขยับวันละ 60 pip นั้นเล็กเกินไปสำหรับตลาดที่ขยับวันละ 700 pip

**สรุป: adaptive ไม่ใช่เครื่องมือหากำไร แต่เป็นเครื่องมือที่ทำให้ค่าชุดเดียวใช้ได้ในสภาพที่ต่างกันมาก** ถ้าไม่มีมัน ต้องมีค่าแยกสำหรับแต่ละตลาด ซึ่งคือการจูนรายตลาดที่โปรเจกต์นี้ห้ามไว้ตั้งแต่ต้น

### ชั้น 2 — เพดานจำนวนไม้

เปิดพร้อมกันได้ **ไม่เกิน 3 ไม้** ไม่ว่าราคาจะแตะกี่ชั้น ทำให้ความเสียหายสูงสุดต่อรอบคำนวณได้ล่วงหน้าโดยไม่ต้องพึ่งสถิติจากอดีต

### ชั้น 3 — รอราคาเด้งก่อนเข้า (Momentum Confirmation)

ราคาแตะเส้นแล้ว**ยังไม่เข้าไม้ทันที** ต้องรอให้ราคาเด้งกลับมา `0.65` ช่องก่อน จึงเข้าที่ราคานั้น เป็นการหลีกเลี่ยงการ "รับมีด" ในขณะที่ราคายังไหลลงต่อ

ราคาที่ต้องจ่ายคือได้ราคาเข้าที่แย่กว่าเดิม และชั้นที่ราคาไม่เด้งเลยจะไม่ถูกเทรด

### ชั้น 4 — เพดานตัดวงจร (Equity Stop)

**ชั้นที่สำคัญที่สุด** ทำงานที่ระดับบัญชี ไม่ใช่ระดับออเดอร์

> ถ้ายอดเงินรวม (นับกำไรลอยด้วย) ต่ำกว่าจุดสูงสุดที่เคยทำได้ **$18** → **ปิดทุกไม้ทันที** แล้วห้ามเปิดใหม่ 350 แท่ง

ต่างจาก stop ของกริดตรงที่ stop ของกริดคุมได้แค่รอบเดียว — ถ้าตลาดเป็นเทรนด์ยาว กริดจะปักหมุดใหม่แล้วโดนอีก วนไปเรื่อยๆ ส่วนเพดานตัดวงจรคุม **ความเสียหายสะสมข้ามหลายรอบ** และบังคับให้หยุดพัก

เพดานนี้ต้องขยายตามขนาดไม้เมื่อทบต้น — ถ้าปล่อยค้างไว้ขณะที่ lot โตขึ้น มันจะหดจนเล็กกว่าสเปรดและหมดความหมาย

### ชั้น 5 — ตัวกรองสภาวะ

ห้ามเปิดไม้ใหม่ขณะ `ATR(10) / ATR(200) > 0.90`

> **ข้อค้นพบสำคัญเกี่ยวกับตัวกรองนี้**
> วัดแล้วพบว่า **66.5% ของค่าตัวกรองนี้อธิบายได้ด้วย "ตอนนี้กี่โมง" เพียงอย่างเดียว** เพราะ ATR(200) บน m5 กินเวลาแค่ 17 ชั่วโมง ซึ่งสั้นกว่าหนึ่งวัน จึงแยกไม่ออกระหว่าง "ตลาดผันผวนผิดปกติ" กับ "ตอนนี้ 11 โมง"
> การขยายหน้าต่างเป็น 1 วัน 5 วัน หรือ 1 เดือน **แก้ไม่ได้** (ลดจาก 66% เหลือแค่ 45% แล้วตัน) เพราะปัญหาอยู่ที่ตัวตั้ง ไม่ใช่ตัวหาร
> มีการทดลองแก้โดยเทียบกับ ATR ของชั่วโมงเดียวกันในอดีต ซึ่งลดเหลือ 6.7% ได้จริง แต่ผลการเทรดดีขึ้นบน EURUSD และแย่ลงบนทองคำ จึงไม่นำมาใช้ (โค้ดอยู่ใน `adaptive.py` ปิดสวิตช์ไว้ที่ `seasonal_vol=False`)

## การตรวจ baseline 3 ด่าน

### ด่าน 1 — Walk-forward: **ผ่าน**

เลือกค่าจากอดีต 3 ปี → เทรดปีถัดไป → เลื่อนไปข้างหน้า → ทำ 16 รอบ ทุกรอบค่าที่เลือกไม่เคยเห็นปีที่เอาไปทดสอบ

```
ปีที่กำไร (ไม่เห็นอนาคต)  : 14/16
ผลรวม out-of-sample      : $497
ค่าที่ล็อกไว้              : $380
```

**ค่าที่ชนะเกาะกลุ่มจริง** — `vol_block` เลือกค่าต่ำ 15 จาก 16 รอบ (94%) ไม่ใช่การกระโดดมั่ว แปลว่าระบบมีโครงสร้างจริง

### ด่าน 2 — ค่าที่ตั้งไว้ปลอดภัยไหม: **ตกครั้งแรก แก้แล้ว**

สแกน 243 ชุดรอบค่าเดิม พบว่า **44 ชุดพอร์ตแตก** จึงเลื่อนช่วงตัวเลขที่ทดสอบไปทางที่ปลอดภัยแล้วสแกนใหม่ 2,500 ชุด

```
รอบแรก (ค่าเดิม)   แตก   44 จาก   243 ชุด  (18%)
รอบสอง (ค่าใหม่)   แตก    1 จาก 2,500 ชุด  (0.04%)
```

### ด่าน 3 — ค่าที่ตั้งไว้ดีที่สุดไหม: **ตกครั้งแรก แก้แล้ว**

ค่าเดิมอยู่อันดับ 92 จาก 243 ชุด คือกลางๆ มี 91 ชุดที่ดีกว่า

**การเลือกค่าใหม่ไม่ได้เลือกชุดที่คะแนนสูงสุด** แต่เลือกชุดที่ **"ชุดข้างเคียงที่แย่ที่สุดยังดีที่สุด"** เพราะค่าที่ต้องตั้งเป๊ะถึงจะรอด จะพังทันทีที่ตลาดจริงต่างจาก backtest

## ข้อผิดพลาดที่พบระหว่างทางและแก้แล้ว

บันทึกไว้เพราะผลลัพธ์ทั้งหมดก่อนการแก้เหล่านี้ใช้ไม่ได้ และเก็บไว้ใน `_invalid_outputs/`

1. **วัด drawdown ผิด** — หารด้วยเงินตั้งต้น $100 แทนที่จะหารด้วยยอดสูงสุดที่ร่วงลงมา ทำให้รายงานว่าทองคำ m15 "พอร์ตแตก 114%" ทั้งที่จริงคือ 22%
2. **ปิดไม้ในแท่งเดียวกับที่เปิด** — เพดานตัดวงจรปิดไม้ได้ในแท่งเดียวกับที่เปิดถึง 86-92% ของครั้ง และได้กำไรขั้นต้นเป็นบวก คือการขาดทุนที่ทำเงินได้ ซึ่งเป็นลายเซ็นของการมองอนาคต
3. **คำนวณ true range ข้ามช่องว่างข้อมูล** — ทองคำมี 466 วันที่ดึงไม่สำเร็จ ทำให้ค่าที่จุดต่อพุ่ง 10-100 เท่า แล้วไหลเข้าค่าเฉลี่ย 200 แท่งไปกำหนดขนาดกริดผิด
4. **Dukascopy ส่งไฟล์ปลอม** — วันที่ยังไม่มีข้อมูลจริงถูกตอบกลับด้วยไฟล์สมบูรณ์ที่ทุกแท่งราคาเท่ากันและ volume เป็นศูนย์ (ทองคำปี 2003 ราคา 1.25 ทั้งเดือน) แก้โดยเพิ่มตัวตรวจใน `quantdata`
5. **ทองคำถูกตัดสินจากข้อมูล 1.4 ปี** เทียบกับ EURUSD 20 ปี แก้โดยดึง Dukascopy ย้อนหลัง 23 ปี
6. **พารามิเตอร์สองตัวไม่เคยถูกทดสอบ** — `atr_fast` และ `atr_slow` เป็นค่า default ที่ถูกล็อกไว้ตลอดทุกการค้นหา และ `atr_slow=200` คือต้นเหตุที่ตัวกรองอ่านนาฬิกาแทนที่จะอ่านตลาด

## ML ควรทำอะไร

ไม่ใช่ทำนายราคา มี 3 ทางเลือก เรียงตามความพร้อมของข้อมูล

1. **ไม้นี้ควรเปิดไหม** — ทุกไม้ในอดีตมีคำตอบจริงอยู่แล้ว เป็น classification ธรรมดา แต่มีแค่ราว 1,300 ไม้ต่อตลาดใน 19 ปี ข้อมูลน้อยและ overfit ง่าย
2. **ช่วงข้างหน้าควรเทรดไหม** — ตรงกับปัญหาช่วงนิ่งที่สุด แต่มีข้อมูลแค่ ~230 เดือน และการทำนายถูกว่าจะเงียบให้ผลลัพธ์แค่ "อย่าเทรด" ไม่ได้ทำให้มีกำไร
3. **ระยะห่างกริดควรเป็นเท่าไหร่** — แทนตัวคูณคงที่ด้วยค่าที่โมเดลเลือก

**โมเดลต้องชนะตัวเลขข้างบนโดยตัดสินด้วยทองคำ** ความแม่นของ classification เพียงอย่างเดียวไม่พิสูจน์อะไร

## ที่ยังไม่ได้ทำ

- **ยังไม่เคยรันจริงหรือ forward test** ทุกตัวเลขเป็น backtest ล้วน
- **ยังไม่ได้ walk-forward ซ้ำหลังแก้ค่า** — ด่าน 1 ผ่านด้วยค่าชุดเดิม ยังไม่ได้ยืนยันด้วยค่าปัจจุบัน
- **การทบต้นยังใช้ไม่ได้** — lot โตจนชนเพดานโบรก แล้วเพดานตัดวงจรหดจนเล็กกว่าสเปรด ตัวเลขที่ได้ (หลักล้าน) เป็นของปลอม ต้องแก้ก่อนจึงจะรายงานได้
- `stop_extra` และ `dd_pause_bars` ยังไม่เคยทดสอบบนค่าชุดปัจจุบัน
- **เดือนที่กำไรยังอยู่ที่ 62-67%** ยังไม่ถึงเป้าที่ต้องการว่าทุกเดือนไม่ควรติดลบ
- ยังไม่ได้ตัดสินใจเรื่องตัวกรองเวลา (ตัดช่วงเอเชีย)
- ยังไม่ทราบสาเหตุของช่วงนิ่ง 54%
- ยังไม่ได้ดึงข้อมูล Nasdaq ย้อนหลัง (ตั้งค่าไว้พร้อมแล้วที่ `NDX100.DUKA`)
- ยังไม่ได้จำลอง slippage ตอนโดน stop — ที่ 2 pip กินกำไรราว 10% ที่ 10 pip หายครึ่ง
- ทองคำไม่มีข้อมูลสเปรดย้อนหลัง ต้นทุนใช้สเปรดคงที่ของโบรกแทน
