# Quant_Grid_ML

ระบบกริดปรับตัวตามความผันผวน ทดสอบบน EURUSD และทองคำ ด้วยทุนตั้งต้น $100
บนข้อมูลย้อนหลัง 20 ปีที่สร้างจาก tick

ชื่อโปรเจกต์มีคำว่า ML แต่ยังไม่มี ML อยู่ในนั้น — ตั้งใจครับ เพราะโมเดลจะวัดผลได้
ก็ต่อเมื่อมี baseline ให้เทียบ และการสร้าง baseline กลายเป็นงานส่วนใหญ่ของโปรเจกต์นี้
ตอนนี้ baseline บอกได้แล้วว่าโมเดลควรไปอยู่ตรงไหน อยู่ในหัวข้อ **ML ควรทำอะไร**

---

## วิธีรัน

ข้อมูลราคามาจากแพ็กเกจกลาง `quantdata` — **ไม่มีอะไรในโปรเจกต์นี้ดึงราคาเอง**

```
python scripts/backtest/plots_current.py     # กราฟ        -> plots/
python scripts/backtest/yearly_results.py    # ผลรายปี      -> results/
python scripts/backtest/stagnation.py        # ช่วงที่เงินไม่โต -> results/, plots/
python scripts/backtest/test_grid.py         # ทดสอบเครื่องยนต์ ต้องผ่านทุกข้อ
```

`params_100usd.json` เก็บค่าที่ทุกสคริปต์อ่าน
`symbol_specs.json` เก็บขนาดสัญญา สเปรด และ swap ที่ดึงสดจาก MT5 — ไม่มีการเดาค่าของโบรก

## กลยุทธ์ทำอะไร

กริดที่ทุกระยะเป็นตัวคูณของความผันผวนปัจจุบัน ค่าชุดเดียวจึงมีความหมายเท่ากัน
ทั้งบนคู่เงินที่ขยับวันละ 60 pip และโลหะที่ขยับวันละ 700 pip

| กฎ | ค่า |
|---|---|
| ระยะห่างชั้น | `4.2 × ATR(20)` ล็อกไว้ตอนปักหมุด |
| จำนวนชั้น | บน 3 ล่าง 3 แต่ **เปิดพร้อมกันได้ไม่เกิน 3 ไม้** |
| การเข้า | วาง limit ที่ทุกชั้น แต่รอราคาเด้งกลับ `0.45` ช่องก่อน — ไม่รับมีด |
| ทำกำไร | 1 ช่อง |
| Stop ของกริด | `(3 + 1.5)` ช่องจากหมุด |
| **เพดานตัดวงจร** | ยอดเงินต่ำกว่าจุดสูงสุด **`$22`** → ปิดทุกไม้ แล้วหยุด 350 แท่ง |
| ประตูกรอง | ห้ามเปิดไม้ใหม่ขณะ `ATR(20) / ATR(200) > 1.15` |
| ย้ายหมุด | เฉพาะตอนไม่มีไม้ค้าง **และ** ราคาออกนอกกรอบแล้ว |

ระยะห่าง stop เป้ากำไร และระยะรอเด้ง เป็นตัวคูณ ATR ทั้งหมด จึงย้ายข้ามสินค้าได้โดยไม่ต้องแก้
เพดานตัดวงจรเป็นค่าเดียวที่เป็นเงินสด และมันต้องขยายตามขนาดไม้ —
ตอนที่ปล่อยให้ค้างไว้ขณะ lot ทบต้น มันเคยหดเหลือ 0.01 pip

**เพดานตัดวงจรไม่ใช่ของเสริม แต่เป็นกระดูกสันหลัง**
ปิดมันแล้วพอร์ตแตกทั้งสองตลาด EURUSD ขาดทุน 440% ทองคำ 588%
ส่วนตัวเลขไม่สำคัญนัก — ทดสอบแล้ว $8 ถึง $45 ใช้ได้ทั้งคู่ และ $22 อยู่กลางย่านนั้น

## ผลลัพธ์

ข้อมูล Dukascopy m5 ยี่สิบปี ค่าชุดเดียว ไม่เคยจูนแยกรายตลาด
**ทองคำไม่เคยถูกใช้เลือกพารามิเตอร์ใดๆ ประวัติทั้งหมดของมันจึงเป็น out-of-sample**

| | EURUSD | ทองคำ |
|---|---|---|
| **lot คงที่ 0.01** | $100 → $594 (9.8%/ปี) | $100 → $1,096 (13.4%/ปี) |
| **ทบต้น** | $100 → $1,672 (16.0%/ปี) | $100 → $21,092 (32.5%/ปี) |
| ปีที่กำไร | 12–13 จาก 19 | 17–19 จาก 19 |
| **ปีกลางๆ** | **+2.2%** | **+9.1%** |
| ปีแย่สุด | −14.6% | −1.4% |
| ขาดทุนหนักสุด | 29% | 37% |

ตารางเต็มอยู่ใน `results/yearly_results.csv`

### อ่านค่ากลาง อย่าอ่านค่าเฉลี่ย

ช่องว่างระหว่างปีกลางๆ กับอัตราทบต้นคือเรื่องทั้งหมด
EURUSD ปีกลางๆ ได้ +2.2% แต่ทบต้นได้ 16% เพราะ **4 ปีจาก 19 ปี** (2008, 2013, 2022, 2024)
แบกอีก 15 ปีไว้ ส่วนทองคำ 4 ปีสุดท้ายทำเงิน 94% ของทั้งหมด

ปีที่หยิบมาสุ่มจากประวัตินี้ ไม่มีอะไรน่าตื่นเต้น ตัวเลขพาดหัวคือรูปร่างของไม่กี่ปีที่พิเศษ
ไม่ใช่รายได้ประจำ

## สิ่งที่ยี่สิบปีบอก

**กำไรมาพร้อมความผันผวน และไม่มีอย่างอื่นที่วัดได้**
กำไรรายปีสัมพันธ์กับความผันผวนของปีนั้น +0.43 (EURUSD) และ +0.38 (ทองคำ)
ส่วนความเป็นเทรนด์ได้ +0.07 และ −0.03 คือไม่เกี่ยวเลย

**มีช่วงเงียบหลายปี และมันเกิดกับทุกตลาดพร้อมกัน**
ปี 2013–2019 ยุคที่ความผันผวนถูกกด ให้ผล $81 และ $91
เทียบกับ $329 และ $309 จากสี่ปีวิกฤต 2008–2011
การกระจายหลายตลาดจึงไม่ช่วยเรื่องนี้ เพราะธนาคารกลางที่กดตลาดหนึ่งก็กดตลาดอื่นพร้อมกัน

**เกือบทั้งหมดทำเงินในช่วงนิวยอร์ก**
96% ของกำไร EURUSD และ 93% ของทองคำ เปิดไม้ระหว่าง 19:00–23:00 เวลาโบรก
ส่วนช่วงเอเชียขาดทุนทั้งสองตลาด
และประตูกรองความผันผวนที่ตั้งอยู่ตอนนี้ บล็อกช่วง London กับ Overlap ไป 82–90%
ซึ่งเป็นช่วงที่กำไรดี แต่ปล่อยช่วงเอเชียผ่านเกือบหมด — **มันกรองผิดด้าน และยังไม่ได้แก้**

## ML ควรทำอะไร

ไม่ใช่ทำนายราคา มี 3 ทางเลือก เรียงตามความพร้อมของข้อมูล

1. **ไม้นี้ควรเปิดไหม** — ทุกไม้ในอดีตมีคำตอบจริงอยู่แล้ว เป็น classification ธรรมดา
   แต่มีแค่ราว 2,500 ไม้ต่อตลาดใน 20 ปี ข้อมูลน้อยและ overfit ง่าย
2. **ช่วงข้างหน้าควรเทรดไหม** — ตรงกับปัญหาช่วงนิ่งที่สุด แต่มีข้อมูลแค่ ~230 เดือน
   และการทำนายถูกว่าจะเงียบ ให้ผลลัพธ์แค่ "อย่าเทรด" ไม่ได้ทำให้มีกำไร
3. **ระยะห่างกริดควรเป็นเท่าไหร่** — แทนตัวคูณ 4.2 ที่ตายตัวด้วยค่าที่โมเดลเลือก

**โมเดลต้องชนะตัวเลขข้างบนใน out-of-sample** ความแม่นของ classification เพียงอย่างเดียวไม่พิสูจน์อะไร

## ที่ยังไม่ได้ทำ

- **ยังไม่เคยรันจริงหรือ forward test** ทุกตัวเลขในนี้เป็น backtest ล้วนๆ
- ยังไม่ได้ทดสอบว่าถ้าตัดช่วงเอเชียทิ้ง ผลจะเป็นอย่างไร ทั้งที่รู้แล้วว่ามันขาดทุน
- ยังไม่ได้แก้ประตูกรองที่กรองผิดด้าน
- ยังไม่รู้สาเหตุของช่วงนิ่ง 91%
- ยังไม่ได้ดึงข้อมูล Nasdaq ย้อนหลัง — การเปรียบเทียบครั้งก่อนที่ทำให้มันดูดี
  ใช้ข้อมูลแค่ 1.4 ปี เทียบกับ EURUSD ยี่สิบปี
- ยังไม่ได้จำลอง slippage ตอนโดน stop ที่ 2 pip กินกำไรราว 10% ที่ 10 pip หายครึ่ง
- ทองคำไม่มีข้อมูลสเปรดย้อนหลัง ต้นทุนใช้สเปรดคงที่ของโบรกแทน
- `_invalid_outputs/` เก็บกราฟและผลทั้งหมดที่สร้างก่อนการแก้ 4 จุด
  **ไม่มีอะไรในนั้นที่ควรอ่านเป็นผลลัพธ์** เหตุผลอยู่ในโฟลเดอร์นั้น
