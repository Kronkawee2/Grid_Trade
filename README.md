# Quant Grid ML — Adaptive Grid Research

EURUSD และ XAUUSD จาก Dukascopy (ข้อมูลสร้างจาก tick ย้อนหลัง 20-23 ปี) มาทดสอบสมมติฐานที่ว่าระบบกริดซึ่งปรับขนาดตามความผันผวนและมีการควบคุมความเสี่ยงที่รัดกุม สามารถสร้างผลตอบแทนที่เป็นบวกอย่างต่อเนื่องบนทุนขนาดเล็ก ($100) ได้จริงหรือไม่ วิธีทดสอบคือสร้าง baseline ที่ตรวจสอบได้ก่อน แล้วเปิดฟีเจอร์ทีละอย่างเพื่อดูว่าอะไรคือสิ่งที่ทำให้ระบบรอด ไม่เชื่อผลรวมที่ดูดี แต่ทุกการเปลี่ยนแปลงต้องผ่านการตรวจ 3 ด่านและทำให้ทั้งสองตลาดดีขึ้นพร้อมกันโดยไม่จูนค่าแยกรายตลาด

ชื่อโปรเจกต์มีคำว่า ML แต่ยังไม่มี ML อยู่ในนั้น เพราะโมเดลจะวัดผลได้ก็ต่อเมื่อมี baseline ให้เทียบ และการสร้าง baseline ที่เชื่อถือได้กลายเป็นงานเกือบทั้งหมดของโปรเจกต์นี้

## ผลการทดลอง

**baseline** ผ่านการตรวจครบ 3 ด่านแล้ว ทำกำไรได้ทุกปี 19/19 ปี ทั้งสองตลาด โดยที่ทองคำไม่เคยถูกใช้เลือกค่าใดๆ เลย

**งานพัฒนาชุดล่าสุด** (เพิ่มความถี่การเทรดจาก 65 เป็น 290 ไม้/ปี) ผ่านด่าน 1 และ 2 ทำให้สัดส่วนเดือนที่กำไรเพิ่มจาก 62% เป็น 89% และกำไรเพิ่ม 82% โดยความเสี่ยงลดลง **เป็นเวอร์ชันแยกต่างหาก ไม่ได้มาแทนที่ baseline** — baseline คือฐานเทียบที่ล็อกไว้ถาวร

สิ่งที่พิสูจน์ได้ชัดเจนคือ **มูลค่าทั้งหมดของระบบอยู่ที่การควบคุมความเสี่ยง ไม่ได้อยู่ที่ตัวกริด** — กริดเปล่าๆ พอร์ตแตกทุกกรณี และตัวที่พลิกจาก "แตก" เป็น "กำไร" คือเพดานตัดวงจร ไม่ใช่กลไกการวางออเดอร์

**สิ่งที่ทำไม่ได้:** เป้าหมาย "ทุกเดือนต้องเป็นบวก" เป็นไปไม่ได้ด้วยระบบนี้ ทดสอบ 2,500 ชุดค่าแล้วสูงสุดได้ 73.6% ของเดือน และหลังพัฒนาต่อได้ถึง 95.2% ซึ่งยังเหลือเดือนแดง 5%

## ทำไมระบบกริดถึงล้างพอร์ต

กริดคือการวางออเดอร์ limit เป็นชั้นๆ รอบราคาปัจจุบัน แล้วเก็บกำไรทีละน้อยเมื่อราคาแกว่งไปมา ปัญหาคือมันสวนทางตลาดโดยธรรมชาติ

* **เมื่อตลาดแกว่งในกรอบ:** ราคาวิ่งขึ้นลงผ่านชั้นต่างๆ เก็บกำไรได้เรื่อยๆ ดูเหมือนเครื่องพิมพ์เงิน
* **เมื่อตลาดวิ่งทางเดียว:** ทุกชั้นถูกเปิดหมดและขาดทุนพร้อมกัน ยิ่งราคาไปไกลยิ่งขาดทุนมาก ไม่มีจุดจบในตัวมันเอง

ระบบกริดส่วนใหญ่จึงมี equity curve ที่สวยงามเป็นเดือนหรือเป็นปี **แล้วจบในวันเดียว** โปรเจกต์นี้จึงตั้งโจทย์ที่การควบคุมความเสียหายก่อน ไม่ใช่ที่การหากำไร

## หลักการทำงานทั้งหมด: 5 ชั้น

ทุกชั้นถูกเพิ่มเข้ามาตามลำดับ และแต่ละชั้นถูกวัดผลแยกว่าให้อะไรบ้าง (ไม่มี Machine Learning เป็นกฎเชิงกลไกล้วน)

### ชั้น 1 — กริดที่ปรับตามความผันผวน (นี่คือคำว่า "adaptive")

ระยะห่างระหว่างชั้นเป็น `atr_mult × ATR` คำนวณใหม่ทุกครั้งที่ปักหมุด แล้วล็อกไว้ตลอดรอบนั้น เป้ากำไร ระยะ stop และระยะรอเด้ง ล้วนเป็นสัดส่วนของระยะห่างนี้ จึงขยายและหดตามไปด้วยทั้งหมด

**วัดแล้วว่ามันช่วยจริงแค่ไหน** โดยเปลี่ยนบรรทัดเดียว: แทน `× ATR` ด้วยตัวเลขคงที่

| ระยะห่าง | EURUSD | maxDD | | ทองคำ | maxDD |
| :--- | ---: | ---: | :--- | ---: | ---: |
| **ปรับตาม ATR** | $594 | **36%** | | **$1,096** | **21%** |
| คงที่ 15 pip | **แตก** | 209% | | — | — |
| คงที่ 25 pip | $248 | 97% | | **แตก** | 236% |
| คงที่ 40 pip | **$685** | 35% | | $351 | 60% |

**บนตลาดเดียว** ระยะคงที่ 40 pip ทำเงินได้มากกว่าเล็กน้อย แต่อีกสี่ค่าจากห้าค่าให้ DD 70-209% หรือพอร์ตแตก ต้องรู้ล่วงหน้าว่า 40 คือคำตอบถึงจะชนะ ซึ่งรู้ไม่ได้

**ข้ามตลาด** ค่าที่ดีที่สุดจาก EURUSD (40 pip) พอย้ายไปทองคำได้ $351 DD 60% เทียบกับ ATR ที่ได้ $1,096 DD 21% — **แย่กว่า 3 เท่า** เพราะ 40 pip ที่พอดีกับตลาดที่ขยับวันละ 60 pip นั้นเล็กเกินไปสำหรับตลาดที่ขยับวันละ 700 pip

**สรุป: adaptive ไม่ใช่เครื่องมือหากำไร แต่เป็นเครื่องมือที่ทำให้ค่าชุดเดียวใช้ได้ในสภาพที่ต่างกันมาก**

### ชั้น 2 — เพดานจำนวนไม้ (`max_open`)

**ค่านี้คุมสองอย่างพร้อมกัน** — จำนวนชั้นกริด และจำนวนไม้ที่เปิดพร้อมกันได้

```
for k in range(1, max_open + 1):     # จำนวนชั้นกริด
if len(open_pos) >= max_open:        # เพดานจำนวนไม้
```

และระยะ stop คำนวณจาก `(max_open + stop_extra) × ระยะห่างชั้น` **ตั้งเยอะ stop จึงไกลตามไปด้วย** ซึ่งเป็นเหตุผลที่ตั้ง 40 ไม่ได้ดีกว่าตั้ง 12 — ชั้นที่ 13-40 ไม่เคยถูกใช้ แต่ stop ถูกดันไปไกล 3 เท่า

### ชั้น 3 — รอราคาเด้งก่อนเข้า (`rebound`)

ราคาแตะเส้นแล้ว**ยังไม่เข้าไม้ทันที** ต้องรอให้ราคาเด้งกลับมาตามสัดส่วนของช่องกริดก่อน เป็นการหลีกเลี่ยงการ "รับมีด" ในขณะที่ราคายังไหลลงต่อ

ราคาที่ต้องจ่ายคือได้ราคาเข้าที่แย่กว่าเดิม และชั้นที่ราคาไม่เด้งเลยจะไม่ถูกเทรด

### ชั้น 4 — เพดานตัดวงจร (`equity_stop`)

**ชั้นที่สำคัญที่สุด** ทำงานที่ระดับบัญชี ไม่ใช่ระดับออเดอร์

> ถ้ายอดเงินรวม (นับกำไรลอยด้วย) ต่ำกว่าจุดสูงสุดที่เคยทำได้ตามที่กำหนด → **ปิดทุกไม้ทันที** แล้วห้ามเปิดใหม่ตามจำนวนแท่งที่ตั้งไว้ (`dd_pause_bars`)

ต่างจาก stop ของกริดตรงที่ stop ของกริดคุมได้แค่รอบเดียว — ถ้าตลาดเป็นเทรนด์ยาว กริดจะปักหมุดใหม่แล้วโดนอีก วนไปเรื่อยๆ ส่วนเพดานตัดวงจรคุม **ความเสียหายสะสมข้ามหลายรอบ** และบังคับให้หยุดพัก

เพดานนี้ต้องขยายตามขนาดไม้เมื่อทบต้น — ถ้าปล่อยค้างไว้ขณะที่ lot โตขึ้น มันจะหดจนเล็กกว่าสเปรดและหมดความหมาย

### ชั้น 5 — ตัวกรองสภาวะ (`vol_block`)

ห้ามเปิดไม้ใหม่ขณะ `ATR(atr_fast) / ATR(atr_slow)` เกินเกณฑ์

> **ข้อค้นพบสำคัญ**
> วัดแล้วพบว่า **66.5% ของค่าตัวกรองนี้อธิบายได้ด้วย "ตอนนี้กี่โมง" เพียงอย่างเดียว** เพราะ ATR(200) บน m5 กินเวลาแค่ 17 ชั่วโมง ซึ่งสั้นกว่าหนึ่งวัน จึงแยกไม่ออกระหว่าง "ตลาดผันผวนผิดปกติ" กับ "ตอนนี้ 11 โมง"
> การขยายหน้าต่างเป็น 1 วัน 5 วัน หรือ 1 เดือน **แก้ไม่ได้** (ลดจาก 66% เหลือแค่ 45% แล้วตัน)
> มีการทดลองแก้โดยเทียบกับ ATR ของชั่วโมงเดียวกันในอดีต ซึ่งลดเหลือ 6.7% ได้จริง แต่ผลการเทรดดีขึ้นบน EURUSD และแย่ลงบนทองคำ จึงไม่นำมาใช้ (โค้ดอยู่ใน `adaptive.py` ปิดสวิตช์ไว้ที่ `seasonal_vol=False`)

| 2. ชุดข้างเคียง | **ผ่าน** | **729/729 ชุดกำไร ไม่มีพอร์ตแตกเลย** · กำไรต่ำสุดยังได้ $1,251 |
| 3. อันดับ | **ตก** | อันดับ 241 จาก 729 |

> **ด่าน 3 ตกไม่ใช่เรื่องความปลอดภัย** — มันบอกแค่ว่ามีค่าที่ทำเงินได้มากกว่า และเกณฑ์ "ต้องอยู่ 25% แรก" ตั้งขึ้นเองโดยไม่มีที่มา การไล่ตามอันดับ 1 คือการเลือกชุดที่โชคดี ซึ่งเป็นสิ่งที่โปรเจกต์นี้หลีกเลี่ยงมาตลอด **ด่าน 2 ที่ผ่านแบบ 729/729 คือตัวที่บอกอะไรจริงๆ**

### ทิศทางที่ตารางรายแกนชี้

```
rebound      0.55 → $2,006   0.65* → $2,252   0.75 → $2,478    ยิ่งสูงยิ่งดี
atr_mult     4.0  → $2,097   4.5*  → $2,259   5.0  → $2,412    ยิ่งสูงยิ่งดี
equity_stop  $4   → $2,221   $6*   → $2,240   $9   → $2,298    ยิ่งสูงยิ่งดี
vol_block    0.7  → $2,551 (DD 24%)   0.8* → $2,259 (DD 16%)   แลกกัน
```

ชุดที่ดีที่สุดที่ผ่านเกณฑ์ DD≤20% และกำไรทุกปี (499 จาก 729 ชุดผ่าน):
`atr_mult 4.5 · rebound 0.8 · vol_block 0.8 · atr_fast 15 · max_open 12 · stop $4`
→ **$2,658 · DD 14.3% · เดือนที่กำไร 95.2% · 276 ไม้/ปี** (ยังไม่ได้ตรวจกับทองคำ)

## เพดานความถี่ของระบบ

ทดสอบ 168 ชุด ไล่ `atr_mult` ลงถึง 1.5 เพื่อหาว่าเทรดถี่สุดได้แค่ไหน

| เป้า | ผล |
| :--- | :--- |
| 300+ ไม้/ปี | **ทำได้** 330 ไม้/ปี ผ่านทั้งสองตลาด |
| 400+ ไม้/ปี | EURUSD ผ่าน แต่**ทองคำ DD 31.5%** เกินเกณฑ์ |
| 500+ ไม้/ปี | 21 ชุดถึงความถี่นี้ **ตกเกณฑ์ทั้งหมด** |
| 600+ ไม้/ปี | 99 ชุดถึงความถี่นี้ **ตกเกณฑ์ทั้งหมด** |

ทำได้สูงสุดถึง 2,101 ไม้/ปี แต่พอเกิน 400 ก็ขาดทุนหรือ DD ทะลุ **เป็นข้อจำกัดทางต้นทุน** — กริดกินกำไรทีละช่อง แต่จ่ายสเปรด 1.8 pip เต็มทุกไม้ ยิ่งกริดแคบ กำไรต่อไม้ยิ่งเข้าใกล้ค่าสเปรด

## เป้าหมาย "ทุกเดือนเป็นบวก"

**ทำไม่ได้** จาก 2,500 ชุดค่า

```
เดือนที่กำไร ≥ 60%  →  938 ชุด
เดือนที่กำไร ≥ 70%  →   10 ชุด
เดือนที่กำไร ≥ 75%  →    0 ชุด        สูงสุดที่ทำได้ 73.6%
```

หลังพัฒนาต่อ ดันได้ถึง **95.2%** ซึ่งยังเหลือเดือนแดง 5%

**เดือนที่ขาดทุนไม่ได้เกิดจากระบบหยุดทำงาน** — วัดแล้วพบว่าเดือนขาดทุนเทรดเฉลี่ย 5.3 ไม้ ส่วนเดือนกำไรเทรด 6.0 ไม้ และไม่มีเดือนไหนที่ไม่มีไม้ปิดเลย มันคือเดือนที่บังเอิญไม้แพ้มากกว่าไม้ชนะ

ระบบที่ทุกเดือนบวกจริงมี 2 แบบเท่านั้น: ไม่มี stop loss (แล้ววันหนึ่งล้างพอร์ต) หรือไม่นับกำไรลอยติดลบ

## ข้อผิดพลาดที่พบระหว่างทางและแก้แล้ว

ผลลัพธ์ทั้งหมดก่อนการแก้เหล่านี้ใช้ไม่ได้ เก็บไว้ใน `_invalid_outputs/`

1. **วัด drawdown ผิด** — หารด้วยเงินตั้งต้น $100 แทนที่จะหารด้วยยอดสูงสุดที่ร่วงลงมา ทำให้รายงานว่าทองคำ m15 "พอร์ตแตก 114%" ทั้งที่จริงคือ 22%
2. **ปิดไม้ในแท่งเดียวกับที่เปิด** — เพดานตัดวงจรปิดไม้ได้ในแท่งเดียวกับที่เปิดถึง 86-92% ของครั้ง และได้กำไรขั้นต้นเป็นบวก คือการขาดทุนที่ทำเงินได้ ซึ่งเป็นลายเซ็นของการมองอนาคต
3. **คำนวณ true range ข้ามช่องว่างข้อมูล** — ทองคำมี 466 วันที่ดึงไม่สำเร็จ ทำให้ค่าที่จุดต่อพุ่ง 10-100 เท่า
4. **Dukascopy ส่งไฟล์ปลอม** — วันที่ยังไม่มีข้อมูลจริงถูกตอบด้วยไฟล์สมบูรณ์ที่ทุกแท่งราคาเท่ากันและ volume เป็นศูนย์ (ทองคำปี 2003 ราคา 1.25 ทั้งเดือน)
5. **ทองคำถูกตัดสินจากข้อมูล 1.4 ปี** แก้โดยดึง Dukascopy ย้อนหลัง 23 ปี
6. **พารามิเตอร์สองตัวไม่เคยถูกทดสอบ** — `atr_fast` และ `atr_slow` เป็นค่า default ที่ถูกล็อกไว้ตลอดทุกการค้นหา
7. **`true_range` คืน NaN ที่แท่งแรก** — ถูกกลบด้วย ffill ทีหลัง ทำงานถูกโดยบังเอิญ
8. **ล็อกค่าแล้วเปลี่ยนทีหลัง** — สแกน 2,500 ชุดโดยล็อก `equity_stop $22` แล้วเปลี่ยนเป็น $18 หลังจากนั้น ทำให้ทั้งไฟล์อธิบายระบบที่ไม่มีใครใช้ **เป็นความผิดพลาดที่เสียเวลามากที่สุดในโปรเจกต์**

## เทสต์เครื่องยนต์

`scripts/backtest/test_adaptive.py` — 12 หมวด 24 ข้อ ป้อนราคาที่คำนวณคำตอบด้วยมือได้ แล้วเทียบกับเครื่องยนต์ รันเสร็จใน 10 วินาที

```
1  ระยะห่างกริด = atr_mult × ATR เป๊ะ
2  ผันผวน 2 เท่า → กริดกว้าง 2 เท่า
3  เพดานจำนวนไม้ 1/2/3 ไม่มีทางเกิน
4  ห้ามปิดไม้ในแท่งเดียวกับที่เปิด        ← บั๊กเก่า
5  true range ไม่ข้ามช่องว่างข้อมูล       ← บั๊กเก่า
6  lot ไม่เกินเพดานโบรก                  ← บั๊กเก่า
7  เพดานตัดวงจรขยายตาม lot               ← บั๊กเก่า
8  สเปรด 2 pip = เสีย 2 pip ต่อไม้เป๊ะ
9  ตลาดวิ่งทางเดียวต้องขาดทุน (ทั้งขึ้นและลง)
10 ตัวกรอง volatility ทำงาน
11 แท่งตลาดปิดไม่ถูกใช้
12 Efficiency Ratio = 1 เส้นตรง, ~0 แกว่ง
```

**บั๊กทั้ง 4 ตัวที่เคยเจอมีเทสต์คุมแล้ว กลับมาเงียบๆ ไม่ได้อีก**

## ML ควรทำอะไร

ไม่ใช่ทำนายราคา มี 3 ทางเลือก

1. **ไม้นี้ควรเปิดไหม** — ทุกไม้ในอดีตมีคำตอบจริงอยู่แล้ว เป็น classification ธรรมดา และเป็นทางเดียวที่จะทะลุเพดานความถี่ 400 ไม้/ปี เพราะถ้าคัดไม้แพ้ออกได้ ระบบจะทนความถี่สูงขึ้นได้
2. **ช่วงข้างหน้าควรเทรดไหม** — ตรงกับปัญหาช่วงนิ่งที่สุด แต่มีข้อมูลแค่ ~230 เดือน และการทำนายถูกว่าจะเงียบให้ผลลัพธ์แค่ "อย่าเทรด"
3. **ระยะห่างกริดควรเป็นเท่าไหร่** — แทนตัวคูณคงที่ด้วยค่าที่โมเดลเลือก

**โมเดลต้องชนะตัวเลข baseline โดยผ่าน 3 ด่านเหมือนกัน** ความแม่นของ classification เพียงอย่างเดียวไม่พิสูจน์อะไร

## ที่ยังไม่ได้ทำ

- **ยังไม่เคยรันจริงหรือ forward test** ทุกตัวเลขเป็น backtest ล้วน
- ชุดที่ดีที่สุด (เดือนกำไร 95.2%) ยังไม่ได้ตรวจกับทองคำและยังไม่ผ่าน 3 ด่าน
- **การทบต้นยังใช้ไม่ได้** — lot โตจนชนเพดานโบรก แล้วเพดานตัดวงจรหดจนเล็กกว่าสเปรด ตัวเลขที่ได้ (หลักล้าน) เป็นของปลอม
- ยังไม่ได้ตัดสินใจเรื่องตัวกรองเวลา (ตัดช่วงเอเชีย)
- ยังไม่ทราบสาเหตุที่แท้จริงของช่วงนิ่ง
- ยังไม่ได้ดึงข้อมูล Nasdaq ย้อนหลัง (ตั้งค่าไว้พร้อมแล้วที่ `NDX100.DUKA`)
- ยังไม่ได้จำลอง slippage ตอนโดน stop — ที่ 2 pip กินกำไรราว 10% ที่ 10 pip หายครึ่ง
- ทองคำไม่มีข้อมูลสเปรดย้อนหลัง ต้นทุนใช้สเปรดคงที่ของโบรกแทน
